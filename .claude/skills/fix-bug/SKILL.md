# Bug Fix & Troubleshooting Guidelines

## When to Use

- ユーザーから「〇〇のエラーが出る」「バグを直してほしい」「動かない箇所がある」などの修正依頼を受けた場合

## Core Principles

1. **規約の遵守 (Enforce Project Rules)**
   - 全体共通のアーキテクチャやコーディング規約（Server Componentの優先、featuresフォルダの責務分離など）については、必ず `.github/copilot-instructions.md` に従ってください。
   - エラーを解決するためだけに、プロジェクトの規約や設計思想を曲げないでください。
2. **問題の切り分け (Isolate the Issue)**
   - エラーがどこで発生しているかをまずは特定します。
     - **Server/DB側**: Prisma のクエリエラー、Server Actions 内の例外、API Route のレスポンス異常など
     - **Client側**: React のハイドレーションエラー、イベントハンドラ内のエラー、ブラウザAPIの呼び出しエラーなど
   - 情報が不足している場合は、推測で修正せず、ユーザーにエラーログや発生手順の共有を求めてください。
3. **安易な `"use client"` の禁止**
   - サーバーコンポーネント（Server Component）で発生したエラーを手っ取り早く解決しようとして、ファイル先頭に `"use client"` を追加するだけの提案は避けてください。
   - コンポーネントツリーの末端にのみ Client Component を配置するという設計原則を保つように修正案を考えてください。
4. **適切なエラーハンドリング**
   - Server Actions や Prisma でのデータ操作においてエラーが起きている場合、`try-catch` ブロックによる適切な例外処理や、ユーザーへのフィードバック（エラーメッセージの返却など）が行えているか確認・提案してください。

## トラブルシューティングの進め方

1. **状況の把握**: 提示されたエラーログや現象をもとに、どこで何が起きているかの仮説を立て、ユーザーに説明します。
2. **原因の特定**: 必要に応じて、特定エリアのコード（関連する Server Actions や UIコンポーネントなど）を提示してもらう、あるいは追加のコンソールログ出力を提案して原因を絞り込みます。
3. **修正案の提示**: 原因が明確になったら、規約に沿った設計を維持したまま、最小限かつ最適な修正コードを提示して承認を得ます。
